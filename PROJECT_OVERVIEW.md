# GostFlow — полное описание проекта

> Подробное описание проекта: что он умеет, как устроен и каковы его ограничения. Если функции нет в списке — её нет.

---

## 1. Что это за проект (в двух словах)

**GostFlow** — программа, которая **автоматически строит блок-схемы по исходному коду** в соответствии с российским
стандартом **ГОСТ 19.701-90** («Схемы алгоритмов, программ, данных и систем. Условные обозначения и правила выполнения»,
входит в ЕСПД). Пользователь загружает файл (или несколько файлов, или целую папку проекта) с кодом — получает набор
блок-схем: по одной на каждую функцию/процедуру плюс схема «основной программы».

Ключевые отличия от обычных «рисовалок» схем:

* строгие **символы ГОСТ** (терминатор, процесс, предопределённый процесс, данные, решение, граница цикла, соединитель,
  комментарий), а не произвольные фигуры;
* поддержка **16 языков**, включая **ассемблер** (x86, ARM, MIPS, RISC-V, AVR, 6502, 68k);
* **интерактивный веб-интерфейс**: вкладки файлов, подсветка «код ⇄ схема», **редактор** (перетаскивание блоков и правка
  текста с автоматической перерисовкой связей), уровни детализации, «разворачивание» вызовов функций;
* работает **локально и без интернета** (кроме одноразовой сборки exe), без внешних сервисов и без ИИ — разбор кода
  выполняют собственные парсеры;
* вывод в **SVG** (векторный), **PNG**, **PDF**; запуск как **консольная утилита**, как **веб-интерфейс** и как
  **оконное приложение для Windows (.exe)**.

**Целевая аудитория:** студенты и преподаватели (лабораторные/курсовые, где требуются блок-схемы по ГОСТ), разработчики,
оформляющие документацию по ЕСПД, все, кому нужно быстро получить схему алгоритма из готового кода.

**Происхождение требований.** Опорные материалы: текст ГОСТ 19.701-90 (PDF) и два образца схем
(сортировка вставками, сортировка пузырьком; в них используются символы «граница цикла», «предопределённый процесс»,
«комментарий» с сигнатурой функции, обозначение присваивания `:=`). Внешний вид схем сознательно повторяет эти образцы.

Рабочее имя: **GostFlow** (пакет `gostflow`). Язык интерфейса и сообщений — **русский**. Лицензия **не выбрана**.
Исходный код написан на Python; никаких обязательных сторонних зависимостей нет
(Pillow нужен только для PNG/PDF).

## 2. Быстрый старт

Требуется Python 3.9+ (используется `ast.unparse`). Для PNG/PDF: `pip install pillow`.

```bash
python flowchart.py                    # без аргументов: веб-интерфейс (откроется браузер)
python flowchart.py prog.c             # схемы в каталог ./flowcharts (SVG)
python flowchart.py my_project/        # вся папка проекта (рекурсивно)
python flowchart.py a.py b.asm -f svg,png,pdf -o out
python flowchart.py a.py --detail structure --expand 2
python GostFlow.pyw                    # оконный режим (двойной щелчок на Windows)
build_exe.bat                          # (Windows) собрать dist\GostFlow.exe
```

## 4. Архитектура: как данные проходят через программу

```
исходный код ──► парсер языка ──► IR (дерево узлов) ──► finalize ──► expand_charts ──► apply_detail
                                                                                         │
 SVG / PNG / PDF ◄── render ◄── prims (примитивы) + модель графа ◄── layout.build_chart ◄┘
```

1. **Парсер** (`lang_*.py`) превращает код в список `Chart` (по одному на функцию + «основная программа»). Тело — дерево
   узлов IR. Каждый узел запоминает номера строк исходника (`line`, `end`).
2. **`ir.finalize`** — нормализует текст операторов, классифицирует блоки (ввод/вывод, вызов функции проекта, обычный).
3. **`ir.expand_charts`** (опционально) — подставляет тела вызываемых функций на место вызова.
4. **`ir.apply_detail`** (опционально) — убирает простые операторы (режимы «структура»).
5. **`layout.build_chart`** — рассчитывает координаты блоков по правилам ГОСТ, выдаёт: список графических примитивов
   (для SVG/PNG) и **модель графа** (блоки + связи с портами, подписями «да/нет», строками кода) для редактора.
6. **`render`** — SVG (собственный генератор), PNG/PDF (Pillow, с суперсэмплингом).
7. **`server`/`webui`** — интерфейс в браузере; **`desktop`** — оболочка в виде окна.

### Модель IR (`ir.py`)

| Узел | Смысл |
|---|---|
| `Proc(text, kind)` | простой оператор; `kind`: `stmt` (до классификации) → `process` / `io` / `predef` / `asm` |
| `If(cond, then, els)` | ветвление (также условный переход в ассемблере, `catch`, `guard`) |
| `Loop(top, bottom, body)` | цикл; условие сверху (`while/for`), снизу (`do-while/repeat-until`) или оба |
| `Switch(expr, cases)` | многоветвевой выбор (`switch/case`, `match`, `when`, Pascal `case`) |
| `Ret(text)` | завершение: `return`, `throw`, `exit`, `hlt`, `ret` |
| `Jump(kind, target)` | `break`, `continue`, `goto` |
| `Label(name)` | метка (рисуется соединителем, только если на неё есть `goto`) |
| `Chart(name, body, signature, comment, kind)` | одна схема (функция или основная программа) |

## 5. Все функции проекта (полный перечень)

### 5.1. Построение схем по ГОСТ 19.701-90

Используемые символы и то, что они означают:

| Конструкция кода | Символ ГОСТ |
|---|---|
| начало / конец схемы; `return`, `throw`, `exit`, `panic`, `hlt`, `ret`, «переход на внешнюю метку» | **Терминатор** (скруглённый прямоугольник) |
| присваивания, выражения, любые простые операторы | **Процесс** (прямоугольник) |
| вызов функции/процедуры, определённой в проекте; `call`/`bl`/`jsr`/`rcall` в ассемблере | **Предопределённый процесс** (прямоугольник с двойными боковыми полосами) |
| `print`, `printf`, `cout`, `scanf`, `cin`, `input`, `readln`, `console.log`, `System.out`… | **Данные** (параллелограмм) |
| `if/else`, `elif`, `switch/case`, `match`, `when`, `try/catch` (как вопрос «Исключение?»), условные переходы в asm | **Решение** (ромб; многовыходное — «шиной» с подписями) |
| `for`, `while`, `do…while`, `repeat…until`, `loop`, `foreach` | **Граница цикла** (пара символов с общим идентификатором `A`, `B`…; условие в верхнем или нижнем символе) |
| `break`, `continue`, `goto`, метки; переходы `jmp`/`b`/`j` в asm | **Соединитель** (кружок с номером; у него подпись с именем метки/«выход из цикла»/«следующая итерация») |
| сигнатура и комментарий над функцией | **Комментарий** (скобка + пунктирная линия у блока «начало») |

Правила оформления, которые соблюдает раскладка:

* поток сверху вниз; линии входят в символ сверху, выходят снизу или справа/слева у «Решения»; стрелки на линиях;
* ветви «Решения» подписываются **«да»/«нет»**; у многовыходного выбора — подписи значений (`case`) и «иначе»;
* при `if` с одной живой ветвью (например, `if x: return`) основная ветвь идёт вниз, «завершающая» — вбок;
* пустая ветвь рисуется «обходом» сбоку, слияния линий смещены;
* для `switch` без `default` автоматически добавляется ветвь «иначе»;
* `break`/`continue`/`goto` не рисуют длинных линий, а используют **парные соединители с одинаковым номером**;
* завершающий `return` заменяет блок «конец» (если поток заканчивается `return`, отдельного «конец» нет);
* недостижимый код после `return/goto` не рисуется (кроме меток, на которые есть переход);
* ширина стандартных символов одинакова, высота зависит от текста; текст переносится по словам; ромб расширяется
  под длинные слова, а не разрывает их;
* под схемой — подпись «Блок-схема: имя».

### 5.2. Оформление текста внутри блоков

Включено по умолчанию (отключается `--keep-assign` / галочкой «:= вместо =»):

* `x = 5` → `x := 5`; `i++` / `i--` → `i := i + 1` / `i := i - 1`; `x += a + b` → `x := x + (a + b)`;
* `for (i = 0; i < n; i++)` → `для i := 0; i < n; i := i + 1`;
* типы в объявлениях убираются: `int x = 5` → `x := 5`; `const auto& v = f()`, `let mut s = 0`, `val x: Int = 1` → без типа;
* объявления **без инициализации** (`int x;`, `int a[10];`) не показываются (включить: `--keep-decl` / «Показывать объявления»);
  многоэлементные объявления `int a[N], i, s = 0;` сворачиваются до инициализированных частей;
* опция «объединять простые операторы» (`--merge N`) — склеивает до N подряд идущих простых операторов в один блок;
* в заголовках циклов слова: `пока …`, `для …`, `до …` (русские), в подписях соединителей — «выход из цикла»,
  «следующая итерация» и т. п.

### 5.3. Классификация блоков

* **ввод/вывод** — по регулярному выражению имён (printf, scanf, cout, cin, print, input, println, readln, writeln, echo,
  `System.out`, `console.log`, `fmt.Print*`, `Console.Write*` и др.) → параллелограмм;
* **вызов пользовательской функции** — если в операторе есть вызов функции, определённой в проекте (в этом же или другом
  файле) → предопределённый процесс. Ввод/вывод имеет приоритет над вызовом;
* `exit(...)`, `abort()`, `panic(...)`, `die()`, `os.Exit`, `System.exit`, `process.exit`… → терминатор.

### 5.4. Поддерживаемые языки (16)

Python, C, C++, Java, C#, JavaScript, TypeScript, Go, Rust, PHP, Kotlin, Swift, Dart, Scala, Pascal/Delphi, ассемблер.
Язык определяется по расширению файла, а для вставленного текста — эвристикой по содержимому; можно задать вручную.
Принимаемые расширения: py, pyw, c, h, cpp, cc, cxx, hpp, hh, hxx, ino, java, cs, js, mjs, cjs, jsx, ts, tsx, go, rs, php,
kt, kts, swift, dart, scala, pas, pp, dpr, lpr, inc (трактуется как Pascal), asm, s, S, nasm, masm, a51, z80, mac.

Особенности парсеров:

* **Python** — на стандартном `ast`: `if/elif/else`, `while`, `for`, `try/except/else/finally`, `with`, `match/case`,
  `break/continue/return/raise`, вложенные функции и классы (методы получают имя `Класс.метод`), строки документации и
  комментарии `#` над функцией попадают в символ «Комментарий»; блок `if __name__ == "__main__":` «разворачивается»;
  импорты/`pass` пропускаются; `else` у циклов не рисуется (выдаётся предупреждение). Нужен Python ≥ 3.9 (для `match` в
  анализируемом коде — интерпретатор ≥ 3.10).
* **C-подобные** (C, C++, Java, C#, JS, TS, Go, Rust, PHP, Kotlin, Swift, Dart, Scala) — собственный лексер и
  рекурсивный разбор (без препроцессора и семантики). Понимает: комментарии, строки (в т. ч. сырые/многострочные),
  препроцессор C (пропускается), атрибуты Rust/Java/C#, теги `<?php … ?>`, шаблоны C++, классы/структуры/интерфейсы/
  `impl`/`trait`/`namespace` (методы становятся отдельными схемами с префиксом класса), конструкторы, методы Go с
  получателем (`Stack.Push`), стрелочные функции и функции-выражения JS/TS, лямбды (как обычные операторы),
  `if/else if/elseif`, `while`, `do…while`, `for` (C-стиль, `foreach`, `for…in/of`, Go `range`, Rust `for … in`),
  Rust `loop`/`match`, Kotlin `when`, Swift `guard`/`repeat`/`do…catch`, Go `switch` без выражения и `select`,
  `switch/case` (в т. ч. «проваливание» пустых `case` объединяется в одну метку), Java-стрелочные `case ->`,
  `try/catch/finally`, `break/continue/goto`, метки, `throw`, `defer`, инициализаторы в Go `if x := f(); cond`.
  Языки без обязательной `;` (JS, TS, Go, Kotlin, Swift, Scala) обрабатываются по правилам перевода строки.
  Прототипы функций, `import/using/package/include/typedef` пропускаются.
* **Pascal/Delphi** — `program/unit`, `procedure/function` (в т. ч. вложенные, методы `Класс.Метод`), `begin…end`,
  `if…then…else`, `while…do`, `for…to/downto…do`, `repeat…until`, `case…of…else…end`, `with`, `try…except/finally`,
  `goto`/метки, `exit/halt/break/continue`; разделы `var/const/type/label` пропускаются.
* **Ассемблер** — см. §5.5.

### 5.5. Ассемблерный режим

Архитектуры (по мнемоникам): x86/x86-64 (Intel и AT&T), ARM/AArch64, MIPS, RISC-V, AVR, 6502, Motorola 68k (частично).

* Комментарии: `;`, `//`, `@`, `#` (при `#` отличается от ARM-непосредственных `#5`), блочные `/* */`.
* Метки `name:`, локальные `.L1:`, числовые `1:` с переходами `1b`/`1f` (разрешаются в уникальные имена), MASM `proc/endp`.
* Директивы (`section`, `global`, `.text`, `db/dw/dd`, `equ`, `org`, `include`, макро-директивы…) и определения данных
  пропускаются; префиксы `rep/lock` учитываются.
* **Деление на схемы:** по `proc/endp`; если их нет — по меткам, на которые есть `call` (каждая такая метка = функция).
  Точка входа (`_start`, `main`, `start`) даёт схему верхнего уровня.
* **Блоки:** подряд идущие команды объединяются в один блок «Процесс» (по умолчанию до 6 команд, настраивается
  `--asm-group`; команды выровнены по левому краю). `--asm-comments` добавляет комментарии исходника.
* **Условные переходы → «Решение» с человеческим условием.** Пара `cmp a, b` + `jl метка` превращается в ромб `a < b`
  (знаковые/беззнаковые варианты, AT&T-порядок операндов распознаётся); учитываются `test`, арифметика перед переходом
  (`dec ecx` + `jnz` → `ecx != 0`), `loop/loope/loopne`, `cbz/cbnz`, MIPS/RISC-V `beq/bne/blt/bge/blez…`, ARM `subs` +
  `bne`, AVR `cp/cpi` + `brlo/brne…`, 6502 `cmp/cpx/cpy` + `beq/bne/bcc…`, флаговые переходы (`jo`, `js`, `jp`, `bmi`…).
  Сама команда сравнения, стоящая прямо перед переходом, из предыдущего блока убирается (чтобы не дублировалась).
* **Переходы:** условный/безусловный переход на метку — соединитель с номером и подписью имени метки; на целевой метке
  — парный соединитель. Переход на неизвестную метку/регистр (`jmp eax`, хвостовой вызов) — терминатор «переход: …».
* **Вызовы:** `call/bl/jsr/rcall/jal/invoke` → предопределённый процесс. **Возвраты:** `ret`, `bx lr`, `jr $ra`,
  `mov pc, lr`, `pop {…, pc}`, `rts`, `rti`, `iret` → терминатор «возврат»; `hlt` → «останов».
* Расширения `a51`/`z80` принимаются, но специфические переходы этих архитектур (например, `djnz`, `jp nz`) отдельно
  **не** реализованы — не обещайте их поддержку.

### 5.6. Уровни детализации и «разворачивание» вызовов

* **Уровень детализации** (`--detail`, выпадающий список в интерфейсе):
  `full` — полная схема; `calls` — только структура (циклы, условия, переходы) + блоки вызовов функций;
  `structure` — только циклы, условия, переходы и завершения, без простых операторов.
* **Разворачивание вызовов** (`--expand N`, флажок «Развернуть вызовы функций внутрь схемы» + глубина 1–5):
  тело вызываемой функции проекта подставляется прямо в схему вызывающей. Блок вызова остаётся, затем идёт тело;
  `return expr` превращается в присваивание `имя := expr`, а ранние `return` — в переход к соединителю «возврат из имя»;
  рекурсия не раскрывается; работает **между файлами проекта**. Сочетается с уровнем детализации (сначала разворот,
  потом фильтрация). Блоки из подставленной функции при клике подсвечивают строки **того файла, где функция определена**.

### 5.7. Проект: несколько файлов и папки

* В интерфейсе: перетаскивание нескольких файлов и **папок** (рекурсивно), кнопка «Выбрать папку проекта…».
  Каждый файл — отдельная **вкладка** со своими схемами; вкладку можно закрыть (×); вкладка показывает число схем или ⚠.
* Пропускаются служебные каталоги: `node_modules, .git, __pycache__, venv, .venv, dist, build, target, .idea, .vs, obj, .gradle`;
  файлы > 2 МБ и сверх 400 файлов не загружаются; для интерфейса показывается число пропущенных.
* Кодировка файла: UTF-8, при ошибке — Windows-1251 (в CLI дополнительно cp866/latin-1).
* Функции из разных файлов «видят» друг друга (блок вызова, разворачивание).
* **Ошибка в одном файле** (например, синтаксическая в Python) не ломает остальные: показывается в его вкладке.
* Экспорт всего проекта: **ZIP (SVG)**, **ZIP (PNG)** (структура папок сохраняется), **один PDF** со всеми схемами.
* Из командной строки: `python flowchart.py папка/ -f svg,png,pdf` — результат раскладывается по подпапкам, PDF общий.

### 5.8. Подсветка «исходник ⇄ схема»

Рядом со схемами показан исходный код с номерами строк. **Клик по блоку** — подсвечивает его строку(и) кода и
прокручивает панель кода; **клик по строке кода** — подсвечивает соответствующие блоки (все совпадающие, во всех схемах
вкладки) и плавно прокручивает к первому. Для групп ассемблерных команд подсвечивается весь диапазон строк; для блоков
из развёрнутой функции чужого файла — открывается вкладка этого файла. Если у блока нет строки — выводится подсказка.

### 5.9. Редактор поверх результата

Кнопка **«Править»** у каждой схемы включает режим редактирования:

* **перетаскивание блоков** мышью/пальцем (привязка к сетке 5 px, не уходит за левый/верхний край); связи, подписи
  «да/нет» и стрелки **перестраиваются автоматически** (ортогональная маршрутизация с обходом блоков);
* **двойной щелчок** по блоку — диалог правки текста; размер блока и форма (ромб, параллелограмм…) пересчитываются
  под новый текст (с тем же алгоритмом переноса, что и на сервере);
* **«↶ Отменить»** и **Ctrl+Z** — отмена перемещений и правок текста; **«Сбросить»** — вернуть автоматическую раскладку;
* пометка «(изменена вручную)» в заголовке схемы; кнопка «Готово» выходит из режима правки (правки сохраняются в
  странице, пока не нажато «Построить схемы» — при этом программа спросит подтверждение);
* **экспорт отредактированной схемы** — кнопки SVG/PNG берут версию из редактора (PNG рисуется в браузере);
  неизменённые схемы экспортируются сервером;
* ограничение: правки не сохраняются в файл проекта и не попадают в серверный PDF/ZIP (они делаются из исходного кода).

### 5.10. Прочие возможности интерфейса

* Загрузка перетаскиванием, выбором файлов, выбором папки или вставкой кода в текстовое поле (код можно править и
  перестраивать, схемы строятся заново по кнопке «Построить схемы»; автоматически — при загрузке файлов и смене
  уровня детализации/разворачивания);
* выбор языка (автоопределение по умолчанию);
* настройки: «:= вместо =», символ «Комментарий», показ объявлений, объединение операторов, глубина разворачивания,
  параметры ассемблера (размер группы, комментарии);
* переключатель **«Масштаб»** (вписать в ширину / реальный размер) у каждой схемы;
* кнопка **«Печать»**: в режиме печати скрываются панели, каждая схема печатается на отдельной странице;
* автоматическая **светлая/тёмная тема** интерфейса (схема всегда на белом фоне);
* предупреждения парсера и построения показываются жёлтой плашкой.

### 5.11. Форматы вывода

* **SVG** — собственный генератор; отдельный шрифт не встраивается (стек: DejaVu Sans, Segoe UI, Arial, Liberation Sans,
  sans-serif); в «интерактивном» SVG (для интерфейса) блоки обёрнуты в `<g class="nd" data-n data-l data-e data-f>`.
* **PNG** — Pillow, суперсэмплинг ×3 для сглаживания, итоговый масштаб ×2; шрифты ищутся в системе (DejaVu, Segoe UI,
  Arial, Liberation).
* **PDF** — Pillow, растровый (150 dpi), по одной странице на схему.
* Без Pillow работают SVG и интерфейс; кнопки PNG/PDF скрываются автоматически.

## 6. Командная строка (`python flowchart.py …`)

Аргументы: список файлов и/или папок; без аргументов — запуск веб-интерфейса.

| Параметр | Назначение |
|---|---|
| `-l, --lang {asm,c,cpp,csharp,dart,go,java,javascript,kotlin,pascal,php,python,rust,scala,swift,typescript}` | задать язык (иначе автоопределение) |
| `-o, --out DIR` | каталог результата (по умолчанию `./flowcharts`) |
| `-f, --format svg,png,pdf` | форматы через запятую (по умолчанию `svg`) |
| `--detail {full,calls,structure}` | уровень детализации |
| `--expand N` | развернуть вызовы функций проекта на глубину N |
| `--merge N` | объединять до N простых операторов в один блок |
| `--keep-assign` | не заменять `=` на `:=` и не упрощать `i++`/`x += 1` |
| `--keep-decl` | показывать объявления без инициализации |
| `--no-comment` | не рисовать символ «Комментарий» |
| `--asm-group N` | ассемблер: макс. команд в блоке (по умолчанию 6) |
| `--asm-comments` | ассемблер: добавлять комментарии из исходника |
| `--serve`, `--port N`, `--no-browser` | запуск веб-интерфейса, порт (по умолчанию 8765), не открывать браузер |
| `--list-langs` | вывести поддерживаемые языки |

Код возврата ≠ 0, если какой-то файл не удалось разобрать.

## 7. Использование как библиотеки

```python
from gostflow import Options, make_charts, render_svg, render_png, render_pdf
charts, warnings = make_charts(source_text, "c", Options(detail="calls", expand=1))
svg = render_svg(charts[0])
```
Для проектов: `from gostflow.core import build_project` — принимает список `{"name", "code", "lang"}` и возвращает
`FileResult` на каждый файл (схемы, предупреждения, ошибка). Модель для редактора: `chart.model` (узлы и связи).

## 8. Веб-сервер и API (`server.py`)

Сервер слушает **только 127.0.0.1** (данные не покидают компьютер). Страница целиком отдаётся по `/`.

| Метод и путь | Назначение |
|---|---|
| `GET /` | страница интерфейса |
| `GET /api/info` | список языков, список расширений, доступность Pillow (`pil`) |
| `GET /api/ping` | «пульс» окна (нужен для автозавершения в оконном режиме) |
| `POST /api/render` | тело: `{files:[{name,code,lang}], lang, options}` → результаты по файлам: схемы (SVG + модель), предупреждения, ошибка |
| `POST /api/export` | то же + `format` (`svg`, `png`, `pdf`, `zip-svg`, `zip-png`), `file`, `chart` (`-1` = все) → файл |

Параметры `options`: `gost_assign, show_comment, keep_decl, merge, asm_group, asm_comments, detail, expand`.

## 9. Оконное приложение (`desktop.py`, `GostFlow.pyw`)

* запускает сервер на **свободном порту**, открывает **отдельное окно без адресной строки** (Microsoft Edge, иначе
  Chrome/Chromium, в режиме `--app`, отдельный временный профиль); если браузера нет — обычная вкладка браузера;
* окно «пингует» сервер каждые 2 с; **через ~8 с после закрытия окна сервер сам завершается** (фоновых процессов нет);
  если окно не открылось, ожидание — 45 с;
* без консоли (`.pyw` / `--windowed`).

## 10. Сборка `GostFlow.exe` (Windows)

`build_exe.bat` ставит `pyinstaller` и `pillow` и выполняет
`PyInstaller --onefile --windowed --name GostFlow --icon icon.ico GostFlow.pyw`. Результат — `dist\GostFlow.exe`: один
файл, не требует установленного Python. Нужны Windows, Python 3.9+ и интернет на время сборки. Сборку выполняет пользователь у себя (см. §12).

## 11. Известные ограничения (честный список)

* **Не реализовано:** разбиение схемы на листы A4 с межстраничными соединителями, рамка и основная надпись (штамп),
  экспорт в Word/draw.io/Visio, проверка схемы на соответствие ГОСТ, пошаговое выполнение, сравнение схем.
  (Это варианты развития, не часть проекта.)
* Парсеры C-подобных языков — упрощённые: без препроцессора, макросов и семантики; нетривиальные шаблоны/макросы могут
  отображаться как обычные операторы; анонимные функции-колбэки показываются одним блоком с `{…}`; горутины
  `go func(){…}()` — одним блоком.
* Выражения `a if x else b` / `return cond ? a : b` / Kotlin `return if … else …` не раскрываются в ветвления;
  лямбды остаются в тексте блока; `for…else`/`while…else` в Python не рисуются.
* Ассемблер: макросы и вычисляемые переходы (`jmp eax`, таблицы переходов) показываются как терминатор; Z80/8051 не
  поддержаны по существу; разбиение на функции эвристическое (по `call`-меткам или `proc/endp`).
* Развёрнутый вызов не подставляет фактические параметры в тело функции (показывается тело как есть).
* `try/catch` изображается как решение «Исключение?»; порядок `else`/`finally` приближённый.
* Ручные правки хранятся только в открытой странице; серверный PDF/ZIP строится без ручных правок.
* PDF растровый; шрифты PNG/PDF зависят от системных (на машине без DejaVu/Arial/Liberation кириллица может не
  отрисоваться в PNG/PDF; SVG при этом зависит от шрифтов браузера).
* Очень большие функции дают очень большие схемы (нет автоматического сворачивания).

## 12. Что проверено и что нет (важно для документации)

**Проверялось:**
* построение схем на примерах для Python, C, C++, Java, C#, Go, Rust, PHP, JS, TS, Kotlin, Swift, Pascal, ассемблера
  (x86 NASM, ARM, MIPS, AVR, 6502); визуальный просмотр результатов (PNG) для Python, C, x86-asm;
* «фаззинг» всех парсеров (обрезанные/перемешанные/битые исходники, таймаут): зависаний и падений не осталось;
* соответствие номеров строк блоков исходному коду (C, Go, Pascal, ассемблер, Python, Kotlin);
* серверное API (рендер проекта, экспорт SVG/PNG/PDF/ZIP, ошибка в одном файле) — через HTTP;
* клиентский JS-код — в Node.js с заглушкой DOM поверх реального сервера (вкладки, построение, режим правки, отмена,
  параметры, детализация + разворот); ядро редактора (`webcore.py`) — раскладка JS совпала с Python до пикселя;
  перетаскивание и правка текста проверены на уровне данных и визуально (через тестовый растеризатор SVG);
* логика оконного режима (автозавершение при отсутствии «пульса»); CLI на файлах и папках.

**НЕ проверялось (не утверждайте, что проверено):**
* реальная сборка **`GostFlow.exe`** и запуск на Windows (не проверялась);
* работа интерфейса **в настоящем браузере** (мышиное перетаскивание блоков, двойной щелчок, диалог, drag-and-drop
  папок, подсветка по клику, печать) — код написан и проверен логически/в Node, но интерактивно не прогонялся;
* Edge `--app` режим на Windows; macOS/Linux-окружения пользователей;
* отсутствуют автоматические тесты в репозитории (проверки были разовыми скриптами) — их стоит добавить.

## 13. Технические заметки для сопровождающего

* `build_exe.bat` намеренно содержит **только ASCII и CRLF**: кириллица в `.bat` в UTF-8 ломала `cmd` (русские слова
  воспринимались как команды). Не добавляйте русский текст в этот файл.
* Веб-страница (HTML/CSS/JS) хранится в Python-строках (`webui.py`, `webcore.py`) — так PyInstaller подхватывает её без
  `--add-data`. JS-ядро (`webcore.py`) специально не использует DOM — его можно тестировать в Node.js.
* Модель графа для редактора строится в `layout.py` (`extract_model`) из помеченных групп примитивов (`("mark", …)`) и
  списка связей (`Block.edges`); размеры/перенос текста в JS (`layoutText`, `decisionInfo`) должны совпадать с
  Python (`layout.py`: `n_process`, `n_decision` и др.) — при изменении констант (ширина символа `W`, `CW`, `LH`)
  правьте оба места.
* Парсеры гарантируют прогресс в циклах разбора (защита от зависаний на битом коде) — сохраняйте это при изменениях.
* Номера строк узлов IR: `line`, `end`, и `src` (индекс файла для развёрнутых блоков) — используются подсветкой.
